# REPORT — спайк session_loopback (P2: loopback-сессия «агент ↔ вьюер»)

**Дата:** 2026-10-01 · **Статус:** ✅ работает: полная loopback-сессия через `rat-mux`, 0 ошибок

## Что это

Первый сквозной «продуктовый» контур без сети: агентская половина (захват → H.264 QSV)
и вьюерская половина (декод → показ) соединяются через **настоящий мультиплексор
`crates/mux`** (продуктовый код, не копия) по in-memory duplex («эмуляция сети»;
mux транспорт-агностичен — следующим шагом сюда встаёт TCP/QUIC).

## Каналы

- **Control** (protobuf из `crates/proto`): `Hello` (capabilities) при старте;
  `Ping`→`Pong` раз в секунду (измерение RTT).
- **Video**: payload = `[frame_id u64][ts_capture_us u64][Annex-B H.264]`;
  flags: `DROPPABLE` (+ `KEYFRAME` при IDR).

## Как запустить

```powershell
. .\scripts\devshell.ps1
cd spikes\session_loopback
cargo run --release
cargo run --release -- --smoke=15
```

- `dropped=125` — кадры, отброшенные при занятом энкодере (EAGAIN; политика «не копить
  задержку»). На вьюере потерь нет: 422/423 доехало, 1 кадр был «в полёте» на остановке.
- RTT ~9 мс — это потолок in-memory варианта (опросные циклы потоков); в реальной сети
  добавится сетевая задержка.
- Матрица допущений: та же машина (i5-7600/HD 630), QSV-энкод, SW-декод.
