# REPORT — спайк encode_qsv

**Дата:** 2026-10-01 · **Статус:** ✅ проверено на целевой машине (Intel QSV работает)

## Цель

Проверить доступность аппаратного H.264-энкодера на этой машине (Intel HD 630, i5-7600).
FFmpeg использован как независимый инструмент проверки железа/драйвера; интеграция
в продукт — отдельная задача (oneVPL / Media Foundation / vendor SDK, фаза P1).

## Что сделано

1. Скачан статический FFmpeg 9.0.2 (essentials build) → `E:\dev\Tools\ffmpeg`.
2. Проверен список энкодеров сборки и выполнен реальный энкод:
   testsrc2 1920×1080@30, 5 c, `h264_qsv`, preset veryfast, global_quality 25.
3. Файл проверен декодированием.

## Результат (фактический)

- Доступны QSV-энкодеры: `h264_qsv`, `hevc_qsv`, `av1_qsv`, `vp9_qsv`, `mjpeg_qsv`, `mpeg2_qsv`
  (а также присутствуют `*_nvenc`/`*_amf` — но на этой машине нет соответствующего железа).
- QSV-энкод: 150 кадров за ~1,2 c (**~128 fps**, **4.2× realtime**), выход ~4 МБ (~6,7 Мбит/с).
- Decode-проверка: exit 0, без ошибок.

## Выводы

- Аппаратный H.264-энкод на этой машине работает (Intel Quick Sync). Для NVENC/AMF нужны
  машины с NVIDIA/AMD GPU — в коде пути абстрагируются (NVENC/AMF/QSV + tile-JPEG фолбэк).
- Скрипт воспроизведения: `run_test.ps1` (в этом каталоге).
- Открытый вопрос для P1: выбрать интеграционный путь QSV в коде (oneVPL напрямую vs
  Media Foundation vs FFmpeg-библиотека) — решается на этапе пайплайна «захват → энкод».
