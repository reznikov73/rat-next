# Решение P0-Б: UI-кит вьюера (egui vs iced)

**Дата:** 2026-10-01 · Статус: **рекомендация зафиксирована по итогам спайков**
(в проектный документ `docs/ARCHITECTURE_DESIGN_*.md` войдёт следующей ревизией).

## Что проверено

Оба кита собраны и запущены на целевой машине (Windows 10 22H2, i5-7600, Intel HD 630):

- `spikes/ui_egui` — egui/eframe 0.36: макет «устройства + видео + статус», smoke OK.
- `spikes/ui_iced` — iced 0.14: тот же макет, smoke OK.

## Сравнение

| Критерий | egui/eframe 0.36 | iced 0.14 |
|---|---|---|
| Лицензия | MIT/Apache-2.0 | MIT |
| Модель | immediate mode | Elm-подобная (update/view + сообщения) |
| Экосистема | богатая: egui_extras (таблицы), egui_dock (док-панели), egui_plot | базовые виджеты; расширений меньше |
| Кастомный рендер (видео) | просто: текстуры / `paint_callback` | возможно (custom shader widget), но сложнее |
| Внешний вид | инженерный, настраиваемый | более «продуктовый» из коробки |
| Драйвер-совместимость (тест-машина) | Vulkan-путь wgpu 30 падает в Intel-драйвере; обойдено DX12-бэкендом | работает из коробки (и с DX12, и без) |
| Стоимость сборки | тяжёлая первая сборка, далее быстрая | тяжёлая первая сборка, далее быстрая |

## Решение

**Основной кит: egui/eframe.** Причины:

1. Скорость сборки функциональности ИНСТРУМЕНТА (файловый менеджер, терминал, док-панели,
   таблицы) — экосистема egui закрывает это готовыми крейтами.
2. Простейший путь к видео-поверхности (текстура → позже child-HWND c D3D11).
3. Лицензии MIT/Apache без вопросов.

**Резерв: iced** — задокументированная альтернатива (тоже собран и работает) на случай,
если в P1 потребуется более «продуктовый» вид/UX.

## Требования, вытекающие из спайков

- На машинах с проблемными Intel Vulkan-драйверами задавать wgpu-бэкенд **DX12** явно
  (в коде/конфиге) — не полагаться на дефолтный выбор бэкенда.
- В тестовую матрицу добавить драйверы Intel/AMD/NVIDIA (в первую очередь при тестах видео).
