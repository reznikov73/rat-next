# Rat Next

Production-grade система удалённого администрирования Windows: агент-служба, вьюер оператора, relay/signaling. Переписывание legacy-решения на Rust. Утверждённый проектный документ — [`docs/ARCHITECTURE_DESIGN_v1.1.md`](docs/ARCHITECTURE_DESIGN_v1.1.md) (читать в первую очередь).

## Структура репозитория

- `crates/` — общие крейты ядра
  - `proto` — схема управляющего протокола (protobuf v0)
  - `common` — утилиты, конфиг, ошибки
  - `transport` — QUIC/ICE/relay-транспорт
  - `crypto` — E2E-крипто (Noise, идентичности, PAKE)
  - `mux` — мультиплексирование каналов
- `bins/` — компоненты: `agent`, `agent-helper`, `relay`, `signaling`, `viewer`
- `spikes/` — исследовательские спайки (вне cargo workspace)
- `scripts/` — devshell и проверки
- `docs/` — проектные документы

## Сборка и проверка (Windows)

Окружение разработки на подготовленной машине: Rust — `E:\dev\Rust`, MSVC BuildTools — `E:\dev\VSBuildTools`.
Свежие шеллы не получают переменные автоматически — сначала активируй окружение:

```powershell
. .\scripts\devshell.ps1      # dot-source из корня репозитория
cargo build --workspace
```

Полный локальный прогон (fmt + clippy + build + test, как в CI):

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\check.ps1
```

CI: `.github/workflows/ci.yml` (заработает после публикации репозитория на GitHub).

## Установщик (setup.exe)

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\build-installer.ps1
```

Собирает `dist\rat-next-setup-<дата>.exe` (нужен Inno Setup 6: `winget install JRSoftware.InnoSetup`).

- Папка по умолчанию: `C:\Program Files\Rat Next` (при установке от администратора);
  без прав администратора — `%LocalAppData%\Programs\Rat Next`. Папку можно изменить в мастере.
- В мастере: ярлык в меню «Пуск» (+ значок на рабочий стол по желанию), опция
  «Запускать при входе в Windows» (задача Планировщика с повышенными правами), «Запустить после установки».
- Ярлыки «Rat Next» запускают мини-лаунчер `rat-elevate.exe`: если служба RatNext
  работает — окно открывается без UAC; если службы нет — Windows разово спросит
  права администратора (агенту нужны повышенные права, см. ниже).
- Службы в установщике больше не предлагаются — они включаются в настройках самой
  программы кнопками «Установить / Запустить / Остановить / Удалить» (Windows запросит права).
- При обновлении поверх установленной версии установщик сам останавливает работающие
  службы RatNext/RatNextRelay и поднимает их обратно после замены файлов.
- Удаление — через «Установленные приложения»: снимает службы, задачу автозапуска и удаляет файлы.

## Служба Windows — доступность с загрузки системы

Основной режим для агентских машин: `rat.exe --install-service` регистрирует
службу **«RatNext»** (автозапуск при загрузке, до входа пользователя). Служба
держит в активной сессии пользователя «хелпер» — обычное приложение Rat Next
с системным токеном, поэтому ввод действует во всех окнах, включая
администраторские. Хелпер автоматически перезапускается при завершении, а при
установке службы задача автозапуска «Rat Next» удаляется (чтобы не было двух
конкурирующих агентов).

```text
rat.exe --install-service          # поставить службу (нужны права администратора)
rat.exe --uninstall-service        # снять службу
rat-relay.exe --install-service    # служба relay (для серверной машины)
rat-relay.exe --uninstall-service
```

У relay так же: служба «RatNextRelay» держит в активной сессии окно и значок
relay (зелёный — работает); повторный запуск `rat-relay.exe` открывает окно
работающей службы, а кнопки управления службой есть в её настройках.

Службы включаются прямо из интерфейса: в настройках Rat Next и в настройках
relay есть кнопки «Установить / Запустить / Остановить / Удалить» (Windows
один раз спросит подтверждение прав). Альтернатива без службы — задача
Планировщика («Запускать при входе в Windows», ставится с повышенными правами).

Журналы: `rat-svc.log` — работа службы агента; `relay.log` — работа службы
relay.

**Экран входа, UAC и блокировка.** Агент под службой видит и защищённый
рабочий стол Windows («Winlogon»: экран входа, окно UAC, экран блокировки):
захват переключается на GDI-снимок этого стола, а ввод направляется туда —
оператор может ввести пароль и разблокировать машину. Для этого агент должен
работать под службой (от SYSTEM); обычный ручной запуск защищённый стол не
видит. В защищённом режиме захватывается основной экран.

> **Права администратора.** Чтобы управлять окнами приложений, запущенных
> от имени администратора, сам агент должен работать с повышенными правами —
> иначе Windows (UIPI) не пропускает туда ввод: мышь/клавиатура действуют
> только в обычных (непривилегированных) окнах. Задача автозапуска ставится
> с повышенными правами; при ручном запуске используйте
> «Запуск от имени администратора».
